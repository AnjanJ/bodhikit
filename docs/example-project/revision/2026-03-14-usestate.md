## The key idea, in plain words
State is the component's memory between renders. `useState` hands you the current value and a setter; calling the setter is how you tell React "re-render me with this new value." React only notices a *new* value — mutate the old array in place and nothing changes on screen, which is why every update builds a fresh copy.

## Words
- **state** — what a component remembers between renders
- **setter** — the function `useState` gives you; calling it asks React to render again with the new value
- **re-render** — React running your component again to draw the new state
- **immutable** — never changed in place; you build a new copy instead

## The example we worked through
```jsx
function TodoList() {
  const [todos, setTodos] = useState([]);          // memory: an array of strings
  function add(text) {
    setTodos([...todos, text]);                    // NEW array: React sees a change
    // todos.push(text); setTodos(todos);          // same array object: no re-render
  }
  return <ul>{todos.map(t => <li key={t}>{t}</li>)}</ul>;
}
```
Notice: the setter receives a value, not an instruction — you describe the next state, React does the rest.
